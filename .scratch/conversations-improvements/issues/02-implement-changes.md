# 02 — 实现对话页面改进

**What to build:** 修改对话页面代码，实现两个核心改进：(1) 点击"新建对话"直接创建会话；(2) 切换历史会话时不自动滚动到底部。

**Blocked by:** 01 — 对话页面改进背景分析

**Status:** ready-for-agent

**功能需求:**

1. **简化新建会话流程**
   - 点击"+ 新建对话"按钮时，直接创建一个空会话
   - 使用默认标题："新的诊断对话"
   - 创建后立即切换到新会话
   - 移除标题输入框 UI 和相关状态

2. **优化历史会话加载体验**
   - 切换会话时，不自动滚动到底部
   - 保持视图在最后一条消息位置
   - 仅在新消息到达（用户发送或 AI 响应）时自动滚动到底部
   - 用户可以主动向上滚动查看历史消息

**技术实现:**

1. **状态管理修改**
   - 删除 `showNewConversation` 状态
   - 删除 `newTitle` 状态
   - 添加 `isInitialLoad` ref 用于区分首次加载和后续更新

2. **滚动逻辑修改**
   - 修改 `useEffect` 依赖，不监听 `activeConversation?.messages` 的初始变化
   - 使用 `useRef` 跟踪当前消息数量，只在消息数量增加时滚动
   - 或者添加 `skipScrollOnNextRender` ref 标志

3. **新建会话处理**
   - 简化 `handleCreateConversation` 为 `handleNewConversation`
   - 直接使用默认标题调用 `createConversation`
   - 移除输入验证和取消逻辑

**验收标准:**

- [ ] 点击"新建对话"按钮直接创建并使用默认标题
- [ ] 新会话创建后立即切换到该会话
- [ ] 切换历史会话时不会自动滚动到底部
- [ ] 发送新消息后自动滚动到底部
- [ ] AI 流式响应时自动滚动到底部
- [ ] 用户可以向上滚动查看历史消息
- [ ] 删除会话功能正常工作
- [ ] 会话列表加载功能正常工作
- [ ] 代码通过 TypeScript 类型检查
- [ ] 代码通过 ESLint 检查

**测试步骤（手动验证）:**

1. 点击"新建对话"，观察是否直接创建会话（无需输入标题）
2. 发送几条消息创建对话历史
3. 再次点击"新建对话"创建另一个会话
4. 点击第一个历史会话，观察是否显示最后一条消息位置
5. 向上滚动查看历史消息
6. 在新会话中发送消息，观察是否自动滚动到底部
