# 04 — 主聊天页面支持 URL 参数和状态恢复

**What to build:** 修改现有的聊天页面，使其支持 URL 参数解析和对话状态自动恢复，实现访问 `/chat/{id}` 时自动加载对应对话。

**Blocked by:** 02 — 前端 API 层添加对话查询和 URL 导航方法

**Status:** ready-for-agent

**Acceptance criteria:**
- [ ] 修改 `src/frontend/app/chat/page.tsx` 支持 URL 参数解析
  - 使用 `useParams()` 获取 URL 中的对话 ID
  - 如果 URL 包含 ID，尝试加载对应对话
  - 如果 URL 不包含 ID，自动创建新对话（保持现有行为）
- [ ] 实现对话状态恢复逻辑
  - 从 URL 读取对话 ID
  - 从对话列表中查找对应对话
  - 找到则激活并高亮，否则创建新对话
  - 显示加载状态或错误提示
- [ ] 点击对话列表项时更新 URL
  - 使用 `router.push('/chat/{conversationId}')` 更新 URL
  - 保持当前对话激活状态
  - 不触发页面刷新（客户端导航）
- [ ] 临时会话转换时更新 URL
  - 临时会话转换为正式会话后，URL 自动更新为新 ID
  - 使用 `router.replace()` 避免增加历史记录
- [ ] 保持现有的侧栏折叠、消息发送、流式响应等功能正常工作
- [ ] 处理边界情况：
  - 对话 ID 不存在：显示错误并创建新对话
  - 网络错误：显示重试按钮
  - 无效的 ID 格式：重定向到 `/chat`

**技术备注:**
- 使用 Next.js 的 `useParams()` 和 `useRouter()` hooks
- 保持与现有代码风格一致
- 注意状态管理的复杂度，避免不必要的重新渲染
- 考虑使用 `useCallback` 优化性能

**与任务 03 的关系:**
- 任务 03 创建独立的动态路由页面
- 任务 04 修改主页面支持 URL 参数
- 两者可以并行开发，最终选择一种方案（或保留两种方案）
