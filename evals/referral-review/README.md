# Referral review offline evaluation

This is the **offline portion of MT-20**, not completed release evaluation. It measures a deliberately simple line reader and the production extraction-validator/checklist path with **scripted Fake output**, against provisional development annotations. No language model, database, credentials or paid provider is used. It does not establish clinical accuracy or time saved.

## Reproduce

Use the repository backend virtual environment. Output directories must be new so the CLI cannot overwrite an existing run.

```bash
src/backend/.venv/bin/python evals/referral-review/run.py --provider baseline --output /tmp/referral-baseline
src/backend/.venv/bin/python evals/referral-review/run.py --provider fake --output /tmp/referral-fake
src/backend/.venv/bin/python evals/referral-review/run.py --provider replay \
  --recording /tmp/referral-fake/recording.json \
  --compare /tmp/referral-fake/report.json --output /tmp/referral-replay
python3 scripts/referral_evaluation_summary.py --check
```

`baseline` reads line prefixes and leaves temporal context empty, then runs production deterministic rules. `fake` generates model-shaped output from source lines (not gold), retains explicit dates, and calls the production Fake Adapter, extraction validator and checklist. This tests the pipeline around a provider, **not** model extraction quality. `replay` revalidates the recording and reruns rules without calling any adapter. Replay of a baseline uses the baseline boundary, rather than claiming to validate model output.

The default split is the ten development packets. All are retained: nine readable packets have fact/finding annotations and one scan has rejection-only gold. Twenty frozen packets are available to the runner only with `--split test --ack-test-exposure`; the checked-in reports do not score this split. Inspecting test errors and tuning against them invalidates any subsequent “unseen” claim. The corpus is public to repository readers, not secret.

`--compare` checks **each case's outcome, diagnostics and counts**, plus aggregate counts. A compensating regression in two different cases cannot hide behind unchanged totals. Version manifests show implementation hashes; replay under changed code is a new regression result, not new evidence about a real model. `--check-gates` exits nonzero for any unmet offline gate. Passing these provisional gates would still not establish release readiness.

`--provider real` always fails before reading samples or creating an output directory, even with `--max-cost-usd`. The internal evaluation ledger now shares global day/month financial reservations with workspace runs, but the CLI still lacks shared dispatch-slot integration, operator authorization binding and durable real recording/recovery. See [ledger scope](../../docs/referral-review/EVALUATION-LEDGER.md). A cost cap or configured API key cannot bypass these remaining MT-20 gates. No unlimited or direct-provider fallback exists. Real execution will also require operator gold review, explicit budget authorization, configured model/prices and shared budget availability.

## What the files mean

Each run produces:

- `report.json`: versioned metrics, per-case differences, denominators, outcomes, local duration and unknown-cost fields; commit plus dirty-worktree flag, implementation SHA-256, Python/dependency environment, corpus and recording hashes.
- `report.md`: readable result and blocker table.
- `recording.json`: synthetic model-shaped output or an explicitly recorded error for every selected packet, bound to corpus and packet hashes. Only Fake/baseline origins are currently accepted. No provider secrets or real-provider recordings exist.
- `status.json`: running, complete or interrupted/failed status. A process interruption never creates a successful final report. An incomplete run without `report.json` is not valid metric evidence. A comparison/gate failure can have a completed report but retains failed command status.

Local timing is wall time for parsing plus offline execution; its successful-sample p95 has an explicit sample count and failures/rejections remain reported. It is not model latency, and it cannot satisfy the ≥20 real-measurement gate. Fake Adapter token counters are discarded; real tokens, known/estimated cost, price version and human-verified citation support remain **null**, not invented zeros.

The public `/evaluation` page imports only an allowlisted aggregate JSON projection generated by `scripts/referral_evaluation_summary.py`. It ships no corpus, source pages, gold or recordings. `evals/` is excluded from deployment. The downloadable summary contains per-field/per-kind counts, version/recording hashes and links via stable limitation IDs; full evidence stays in this repository.

## Scoring definitions

All ratios keep numerator and denominator. An empty denominator is null, not 100%. Within each packet:

- **Fact match:** multiset of `(field, raw value, assertion status, temporal context)`. Only literal `Medications: ` and `Report: ` labels are removed, because the production extraction contract preserves full lines while the fixture values omit those labels. No case folding, date guessing, dose/unit conversion or negation erasure. Duplicate output contributes FP. Missing predictions contribute FN, including on a failed readable packet.
- **Finding match:** multiset of `(rule, kind, field)` within the packet; aggregation therefore preserves the required packet key. TP/FP/FN and precision/recall are also broken down by kind. Clean negative packet false-positive rate, item counts and identity false positives are separate.
- **Citation integrity:** accepted facts with at least one reference and **all** references present with correct document, page, quote, code-point offsets and hash, divided by all accepted facts.
- **Provisional support agreement:** exact fact semantics match the annotation and every valid cited span lies within an annotation-supported span. This is an annotation-agreement proxy, not a completed human semantic audit. Pending operator review keeps `human_verified_citation_support` null.
- **Missing / invalid / unsupported citations:** separate fact-level counts for no reference, malformed/nonexistent anchor, and valid anchors lacking annotated semantic support. Pre-validation candidate diagnostics are separate from accepted-result metrics, so a rejected false quote does not disappear or count as adopted evidence.
- **Unannotated facts:** prediction FP; **critical** counts cover name, DOB, medications, allergies and report descriptions. These are not automatically hallucinations: a date/context disagreement is a mismatch but may reflect provisional label misalignment. `lexically_absent_values` separately counts raw values absent from all source pages, a limited fabrication signal. Full semantic hallucination and granular drug/dose/numeric-unit judgments still require operator review; report descriptions are a conservative aggregate, not a claimed unit-level score.
- **Input rejection:** rejected-only gold contributes to total/rejection counts, not invented fact denominators. Expected rejection codes are mapped to production parser codes and mismatches fail the offline outcome gate. Failed readable packets retain all gold false negatives. Gate metrics are reported separately from real release readiness.

See [baseline](reports/2026-10-22-baseline-dev/report.md), [Fake](reports/2026-10-22-fake-dev/report.md), [replay](reports/2026-10-22-replay-dev/report.md), and [failure analysis](FAILURES.md).

| Development-only count | Baseline | Fake pipeline | Replay of Fake |
| --- | --- | --- | --- |
| Packets succeeded / rejected / failed | 9 / 1 / 0 | 9 / 1 / 0 | 9 / 1 / 0 |
| Fact TP / FP / FN | 69 / 5 / 4 | 71 / 3 / 2 | 71 / 3 / 2 |
| Finding TP / FP / FN | 9 / 1 / 1 | 10 / 1 / 0 | 10 / 1 / 0 |
| Accepted fact citation integrity | 74 / 74 | 74 / 74 | 74 / 74 |
| Clean packets with extra findings | 1 / 2 | 1 / 2 | 1 / 2 |

These counts do not pass the complete release gate. No gold was changed, failed sample removed or threshold lowered to improve them. Remaining MT-20 work: human gold review, integration of the ledger with the real runner, authorized real recordings, held-out assessment, human semantic support/hallucination review, ≥20 real latency samples and final regression/release evidence. Existing PostgreSQL/global-reservation concurrency and other prerequisite acceptance remain separate blockers.
