# Chat 页面标题动态管理规范

## Problem Statement

当前 MediTrace 的 `/chat` 页面在以下场景中标题显示不够智能：
1. 无 ID 访问时（新对话），标题显示为固定的"MediTrace 对话"
2. 有 ID 访问时（选择已有对话），标题不显示该对话的实际标题
3. 用户发送新消息后，左侧对话列表和右侧内容区域的标题不会自动更新

用户希望实现类似 Doubao 聊天页面的体验：标题能根据当前对话状态动态变化，并在用户提问后自动更新。

## Solution

实现智能标题管理系统：
1. **URL 无 ID 时**：显示"新的对话"或类似占位标题
2. **URL 有 ID 时**：自动加载并显示该对话的标题
3. **用户提问后**：根据用户的第一条消息自动提取并更新对话标题（左右两侧同步更新）

## User Stories

1. 作为用户，当我访问 `/chat` 且 URL 无 ID 时，我希望看到一个新的空白对话页面，标题显示为"新的对话"，这样我知道正在开始新对话
2. 作为用户，当我从左侧列表选择某个已有对话时，我希望页面标题自动显示该对话的标题，这样我能清楚当前对话内容
3. 作为用户，当我通过 URL 直接访问某个对话（如 `/chat?id=xxx`）时，我希望标题显示该对话的标题，这样我能立即识别对话内容
4. 作为用户，当我在新对话中发送第一条消息后，我希望对话标题自动更新为与我的问题相关的内容，这样我能更容易区分不同的对话
5. 作为用户，我希望左侧对话列表和右侧内容区域的标题同步更新，这样界面保持一致性
6. 作为用户，我希望标题更新是自动的，不需要手动操作，这样体验更流畅
7. 作为用户，我希望标题基于我的第一条消息自动生成，这样标题能准确反映对话主题
8. 作为开发者，我希望标题更新逻辑与消息发送逻辑解耦，这样代码更易维护
9. 作为开发者，我希望标题更新失败时不影响消息发送，这样系统更健壮
10. 作为用户，我希望标题更新有适当的加载状态提示，这样我知道系统正在处理

## Implementation Decisions

### 模块修改
- **前端组件**: `src/frontend/app/chat/page.tsx`
  - 添加 URL 参数解析逻辑（使用 `useSearchParams`）
  - 根据 URL ID 加载对应对话
  - 实现标题自动更新逻辑
  - 修改标题显示逻辑

### 接口变更
- **新增 API 调用**: 在 `src/frontend/lib/api.ts` 中已有 `updateConversation` 函数，可直接使用
- **标题生成策略**: 基于用户第一条消息的前 50-80 个字符，或提取关键问题词

### 技术决策
1. **URL 参数读取**: 使用 Next.js 的 `useSearchParams` hook 读取 `?id=` 参数
2. **标题更新触发点**: 在用户发送第一条消息后（AI 回复前）触发标题更新
3. **标题生成规则**: 
   - 取用户消息前 50 个字符
   - 去除标点符号结尾
   - 添加省略号（如果截断）
4. **错误处理**: 标题更新失败仅记录日志，不影响消息发送
5. **状态管理**: 使用现有 `activeConversation` 状态，更新时同步刷新左侧列表

### 标题更新流程
```
用户发送消息 
  → 消息添加到对话
  → 提取标题（基于消息内容）
  → 调用 updateConversation API
  → 更新本地状态（activeConversation + conversations 列表）
  → UI 自动刷新
```

## Testing Decisions

### 测试标准
- 只测试外部可观察的行为，不测试实现细节
- 验证标题在不同场景下的正确显示
- 验证标题自动更新的完整流程

### 测试场景
1. **场景 1**: 访问 `/chat`（无 ID）→ 标题显示"新的对话"
2. **场景 2**: 访问 `/chat?id=xxx` → 标题显示该对话的现有标题
3. **场景 3**: 从左侧列表点击对话 → 标题显示该对话的标题
4. **场景 4**: 新对话发送第一条消息 → 标题自动更新为消息内容摘要
5. **场景 5**: 已有对话发送新消息 → 标题不改变（仅第一条消息触发）
6. **场景 6**: 标题更新失败 → 消息正常发送，标题保持原样

### 测试方法
- 手动浏览器测试（遵循项目规范：禁止自动对话测试）
- 提供详细的测试步骤供用户手动验证
- 验证 URL 参数、标题显示、API 调用（通过浏览器开发者工具）

## Out of Scope

1. **标题编辑功能**: 用户手动修改标题（已有三点菜单的重命名功能）
2. **多语言标题**: 当前仅支持中文
3. **标题长度限制优化**: 超出长度的处理已有滚动动画，不在本需求范围内
4. **AI 生成标题**: 不使用 AI 分析消息内容生成更智能的标题（仅简单截取）
5. **标题历史记录**: 不记录标题变更历史
6. **URL 路径参数**: 当前使用查询参数 `?id=`，不改为路径参数 `/chat/xxx`

### 关键修改点
1. **URL 参数读取**（新增）:
   ```tsx

   const conversationId = searchParams.get('id');
   ```

2. **标题状态管理**（修改）:
