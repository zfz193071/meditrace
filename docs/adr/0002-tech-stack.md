# ADR 0002: 技术栈选择

**状态**: 已接受
**日期**: 2024
**决策者**: 项目团队

---

## 背景

在确定项目方向后，需要选择合适的技术栈。约束条件：
- 时间：1-2 周完成 MVP
- 硬件：Intel Mac + 8GB 内存（无法本地训练大模型）
- 目标：展示 AI + Web3 全栈能力

## 考虑的方案

### 大模型方案

#### 方案 A: 本地开源模型 (Llama 3 + MLX)

**描述**: 在本地 Mac 上运行开源大模型。

**优点**:
- 无 API 费用
- 完全控制
- 展示本地部署能力

**缺点**:
- Intel Mac 无 Neural Engine 加速
- 8GB 内存不足以运行 7B+ 模型
- 需要额外配置和优化时间

#### 方案 B: DeepSeek API

**描述**: 通过 API 调用 DeepSeek 大模型。

**优点**:
- 无需本地资源
- 性能稳定
- 快速集成
- 成本低（有免费额度）

**缺点**:
- 依赖外部服务
- 需要 API Key
- 数据需上传到云端

#### 方案 C: 混合方案 (API + 微调小模型)

**描述**: API 为主，同时微调一个小模型作为备份。

**优点**:
- 冗余设计
- 展示微调能力

**缺点**:
- 时间成本高
- 复杂度增加

### 前端方案

#### 方案 A: Next.js

**描述**: React 全栈框架，支持 SSR 和 API Routes。

**优点**:
- 雇主需求高
- 生态成熟
- 易于部署到 Vercel
- 可展示全栈能力

**缺点**:
- 学习曲线略陡

#### 方案 B: React + Vite

**描述**: 纯前端 SPA，后端完全分离。

**优点**:
- 开发速度快
- 简单直观

**缺点**:
- 无法展示 SSR 能力
- 需要额外部署后端

#### 方案 C: Vue 3 + Nuxt

**描述**: Vue 生态的全栈框架。

**优点**:
- 国内雇主多

**缺点**:
- 与之前项目技术栈不一致

### 区块链方案

#### 方案 A: Ethereum Mainnet

**描述**: 部署到以太坊主网。

**优点**:
- 最主流
- 真实价值

**缺点**:
- Gas 费用高
- 需要真实 ETH
- 部署后难以修改

#### 方案 B: Ethereum Testnet (Sepolia)

**描述**: 部署到测试网络。

**优点**:
- 免费测试币
- 真实环境模拟

**缺点**:
- 仍需等待确认
- 可能不稳定

#### 方案 C: 本地 Hardhat 网络

**描述**: 本地运行的以太坊节点。

**优点**:
- 开发最快
- 无需等待确认
- 完全控制
- 演示方便

**缺点**:
- 非真实环境
- 重启后数据丢失

## 决策

### 大模型：方案 B (DeepSeek API)

**理由**:
1. 硬件限制：Intel Mac + 8GB 无法本地运行大模型
2. 时间约束：API 集成比本地部署快 3-5 倍
3. 效果保证：API 模型质量高于本地小模型
4. 成本可控：免费额度足够 MVP 开发

**缓解依赖风险**:
- README 中说明可替换为其他 API
- 预留模型抽象层，便于切换

### 前端：方案 A (Next.js)

**理由**:
1. 雇主价值：Next.js 是主流技术栈
2. 全栈能力：可展示前后端统一
3. 部署便利：Vercel 一键部署
4. 生态成熟：组件库丰富

### 区块链：方案 C (本地 Hardhat)

**理由**:
1. 开发效率：本地链确认即时，无需等待
2. 演示便利：可完全控制节点状态
3. 成本为零：无需购买测试币
4. 可迁移：合约代码可轻松部署到测试网

**补充**: 在 README 中提供部署到 Sepolia 测试网的指南

## 最终技术栈

| 层级 | 技术 | 版本 | 理由 |
|------|------|------|------|
| 前端 | Next.js | 14.x | 全栈能力展示 |
| 前端样式 | Tailwind CSS | 3.x | 快速开发 |
| 后端 | FastAPI | 0.100+ | Python 异步，适合 AI 集成 |
| 大模型 | DeepSeek API | - | 硬件限制下的最优选择 |
| 区块链 | Solidity | 0.8.20 | 主流智能合约语言 |
| 区块链开发 | Hardhat | 2.x | 本地开发最快 |
| 区块链交互 | Ethers.js | 6.x | 现代 JavaScript 库 |
| 存储 | IPFS (Pinata) | - | 去中心化存储 |
| 部署 | Vercel + Render | - | 免费托管 |

## 后果

### 正面后果

- 开发速度快，2 周内可完成
- 技术栈多元化，展示全栈能力
- 成本低，适合个人项目
- 文档丰富，遇到问题易解决

### 负面后果

- 依赖 DeepSeek API（需 API Key）
- 本地区块链非真实环境
- 需要说明硬件限制原因

### 缓解措施

- README 中说明 API 可替换
- 提供测试网部署指南
- 在文档中解释技术选型理由
