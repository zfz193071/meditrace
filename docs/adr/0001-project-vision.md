# ADR 0001: 项目愿景与方向选择

**状态**: 已接受
**日期**: 2024
**决策者**: 项目团队

---

## 背景

我们需要创建一个结合大模型与 Web3 的实战项目，目标是展示全栈能力并获得雇主关注。面临的关键决策是：选择哪个领域？Web3 在其中扮演什么角色？

## 考虑的方案

### 方案 A: 金融领域 + 去中心化交易

**描述**: 构建基于 AI 的投资建议系统，交易通过智能合约执行。

**优点**:
- 金融数据公开易获取
- 交易场景与 Web3 天然契合
- 雇主熟悉度高

**缺点**:
- 合规风险高（涉及投资建议）
- 需要真实市场数据接口
- 测试成本高（涉及真实资金）

### 方案 B: 医学领域 + 数据溯源

**描述**: 构建医疗 AI 诊断辅助系统，诊断记录上链确保可审计。

**优点**:
- 医疗合规是热点话题
- 数据溯源需求真实存在
- 公开医学数据集丰富
- 无真实资金风险

**缺点**:
- 医学专业知识门槛高
- 需要处理隐私问题
- 免责声明要求严格

### 方案 C: 医学领域 + 模型市场

**描述**: 训练医疗模型作为 NFT 出售，用 token 支付调用费用。

**优点**:
- Web3 元素更突出
- 商业模式清晰

**缺点**:
- 模型训练成本高
- NFT 市场热度下降
- 实现复杂度大

## 决策

**选择方案 B: 医学领域 + 数据溯源**

### 决策理由

1. **可行性**: 1-2 周时间内可完成 MVP
   - 使用 API 而非本地训练，降低技术门槛
   - 数据溯源比模型市场更容易实现

2. **雇主价值**: 展示多维度能力
   - AI 能力：RAG、对话系统
   - Web3 能力：智能合约、链上验证
   - 工程能力：完整部署、文档

3. **商业故事**: 医疗合规是真实痛点
   - 监管要求诊断记录可追溯
   - 区块链提供不可篡改的解决方案
   - 有明确的 target customer

4. **风险控制**: 无真实资金/医疗风险
   - 明确免责声明
   - 不提供确诊功能
   - 数据匿名化处理

## 后果

### 正面后果

- 项目范围清晰，可在 2 周内完成
- 技术栈多元化，展示全栈能力
- 有明确的商业应用场景
- 文档和演示材料易于准备

### 负面后果

- 医学专业知识需要额外学习
- 需要处理隐私和合规问题
- 不能涉及真实医疗诊断

### 缓解措施

- 使用公开医学数据集，避免真实患者数据
- 所有输出附带明确免责声明
- 强调"辅助建议"而非"诊断"

## 验证标准

项目成功完成的标准：

- [ ] 核心功能可演示（对话 + 上链 + 验证）
- [ ] 完整部署文档
- [ ] README 清晰说明项目价值
- [ ] 演示视频展示完整流程
