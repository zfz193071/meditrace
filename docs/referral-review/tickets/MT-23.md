# MT-23 求职作品包装与演示材料

目标：让雇佣者能快速理解业务价值，并深入检查实现质量。

先读：PRODUCT 求职定位、真实评估和 acceptance report。范围：英文 README、`/evaluation`、视频脚本／成片、作品说明和 Discord 文案文件。

## 实施范围

- README 首屏讲清用户／任务／演示／代码；附架构、运行方式、评估、取舍、限制和许可证。
- `/evaluation` 展示已测版本、真实／replay 区分、分母、失败案例和费用；不能发布私人日志或凭据。
- 录制 60—90 秒英文字幕演示：资料问题→双侧证据→人工处理→新版资料→交接导出。
- 固定示例录制可自动进行非 AI 操作；真实 AI 触发由用户手动完成。录屏不得切换用户前台或包含私人窗口。
- 准备 Discord 求职帖与短项目说明，明确希望承担 AI 应用／全栈工作，链接 demo／代码／评估；本票只写文案，不代用户发送。

## 验收

- [ ] 成片文件／可访问链接存在且可播放，时长和字幕满足要求；不是仅交脚本。
- [ ] 文案中的功能、指标、成本、模型和状态可追溯到实际证据。
- [ ] 不宣称临床验证、已有客户／节省比例／合规认证；固定示例不伪装为即时 AI。
- [ ] README 支持开发者按说明运行 Fake 演示，不需要支付密钥即可理解项目。
- [ ] 公共内容无真实患者资料、秘密或失效相对链接。

验证：链接／媒体检查、从干净配置复核运行说明、文案逐项证据对照。
