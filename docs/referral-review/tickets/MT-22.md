## PDF 上传、重放和解析失败闭环（2026-10-27）

在 `test_workflow_integration.py` 增加 PDF 表单／无 Content-Length 分块上传的 API 集成用例，使用已有公开／开发集合成 PDF；不访问冻结集标注，也不运行模型质量测量：

- 两种传输均保存可解析 PDF；相同 key／内容返回同一 Document，改变内容后返回 `409 IDEMPOTENCY_CONFLICT`，业务表、原件字节、存储预留及清理任务不变。下载的 SHA-256／字节和私有缓存、附件、安全响应头均验证。
- 切换其他账号、删除和到期后，两种上传方式对旧 key 重放及新 key 请求均返回 `404 NOT_FOUND`。分块生成器没有被消费，验证服务端在读取上传正文之前拒绝；原件／元数据／页面同样不可读，没有新增文件或费用。
- 扫描 PDF 返回 `201 rejected` 并带 `PDF_UNREADABLE_PAGE` 和错误页号；重放仍为同一拒绝结果，尝试纳入来源版本返回 422。已有原文、审核快照与授权导出保持可用；新 key 导入可解析 PDF 并保存新版本后，旧快照只派生历史标记，payload／hash 保持不变，Fake 次数不增加。
