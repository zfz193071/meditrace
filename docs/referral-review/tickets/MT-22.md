# MT-22 集成、故障、权限与可用性验收

目标：所有模块组合成完整任务，验证工单之间的接缝。

先读：[Q01—Q20 与工程检查](../QUALITY-AND-RELEASE.md)。范围：跨模块 API／数据库／UI／导出测试、CI 和验收报告。

## 实施范围

- 全链路覆盖导入→版本→Fake run→审核→确认→导出→变更→重新审核→删除；AI Fake run 通过 API 测试执行，不通过自动浏览器。
- 所有子资源访问做双账号测试；支付、幂等、并发预算、未知费用、解析失败、stale 和清理竞争覆盖。
- CI 串联契约生成、前端类型／build／交互、后端测试、PostgreSQL 集成、fixture/replay 评估、部署脚本离线测试。
- 浏览器固定示例、证据高亮、键盘／窄屏、人工修改／导出检查；PDF 真实渲染。
- 写 `acceptance-report.md`，列 Q01—Q20 的证据、运行版本、实际外部集成与缺项，补齐必要修复。

- 将求职核心路径纳入整体验收：无登录进入三个案例、定位证据、人工处理、确认与导出；检查首页、README、视频及评估的实际版本一致，不能用后端测试数量替代模型质量。

## 验收

- [ ] Q01—Q20 全通过，无关键 skipped；PostgreSQL 测试真实运行。
- [ ] CI 不含付费模型密钥，Fake／replay 测试网络不能意外访问真实模型。
- [ ] 跨包／跨账号／历史版本／已删除数据的所有路径正确隔离。
- [ ] 断网、刷新、超时和重复点击不会导致重复费用、人工内容覆盖或错误成功状态。
- [ ] 三种视口、键盘、PDF 和英文文案通过；无可达高危漏洞或阻断缺陷。

- [ ] 核心演示没有登录／支付阻碍，三类案例及下载可用，代码／评估入口有效；无证据的提效或新西兰医疗适配声明已移除。

验证：整套 CI／本地等效命令与背景浏览器检查，记录提交版本和脱敏证据；修复后仅重跑受影响和必要集成检查。
