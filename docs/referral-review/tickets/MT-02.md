# MT-02 领域数据、追加迁移与事务

目标：建立资料版本、证据、审核和账本的持久数据基础。

先读：[数据实体与约束](../DOMAIN-AND-API.md)。范围：新 SQLAlchemy 模型、仓储、事务、Alembic；不修改旧 conversations/messages 内容。

## 实施范围

- 为契约中的 `rr_` 实体创建追加迁移，外键、唯一键、状态 CHECK、归属索引、复合索引及 UTC 时间类型齐全。
- 同一 revision 成员只允许引用本包 Document；Evidence 必须指向该 run 的版本；跨实体关系服务端验证。
- 封装事务单元、稳定加锁顺序、乐观并发和迁移版本检查；启动不建表，不自动跑未审查迁移。
- PostgreSQL 为并发行为权威；SQLite 支持纯领域／快速仓储测试，不使用 SQLite 结果宣称锁已验证。
- 提供独立测试 schema 初始化／清理脚本和迁移 runbook，测试清理仅限本次生成且确认的 schema。

## 验收

- [ ] 空库初始化和保留旧表的数据库升级均成功，第二次执行不重复迁移。
- [ ] 旧表／行保持原样，迁移失败回滚事务，应用回滚不会删新数据。
- [ ] 非法状态、重复事件／批次账本、跨包成员被拒绝。
- [ ] PostgreSQL 双事务同时修改 revision 或扣减同一账本时满足唯一／并发约束。
- [ ] 测试环境无生产默认连接，缺 TEST_DATABASE_URL 时明确 skipped，最终集成验收不能以 skipped 通过。

验证：迁移集成测试和关键约束／竞争测试；保存可复现命令与去敏结果。
