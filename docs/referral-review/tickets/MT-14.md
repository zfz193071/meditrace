# MT-14 工作区、导入与执行状态 UI

目标：用户能完成资料准备并理解处理状态、收费边界和失败恢复。

先读：[页面与流程](../PRODUCT.md)、DOMAIN 路由和错误码。范围：`/workspace`、packet 工作台、类型化 API client。

## 实施范围

- 包列表、创建、重命名、剩余保留期、删除确认；无数据／权限过期／加载／失败状态。
- 文件逐个上传和解析、文本录入、文件级错误／限制、候选文件与已保存 revision 区分。
- 显式保存 revision，未保存修改离开提醒；登录／支付回跳恢复最后已保存草稿。
- AI 按钮提前展示会员／模式／消耗一次额度；运行时显示真实阶段与 elapsed，不伪造进度百分比。
- execute 前创建 pending，前端轮询状态；请求超时转查询，禁止 UI 自动重新调用 execute。
- 手动整理入口和 unavailable/fake/real 标识可见，模型不可用时仍能完成手工任务。

## 验收

- [ ] 操作顺序、边界错误、解析失败和 409 能理解且不会丢已保存资料。
- [ ] 刷新、断网、session 过期、unknown 均有明确状态，不能卡在永久 spinner。
- [ ] 原文不写 localStorage／URL／analytics；API 请求符合生成类型。
- [ ] 桌面与窄屏布局可用，键盘能导入、选择和保存，状态有可访问文本。
- [ ] 自动化 UI 测试只验证预载状态与非生成动作，真实核对由用户手动触发。

验证：组件／API client 测试、背景浏览器非 AI 操作和规定视口检查。
