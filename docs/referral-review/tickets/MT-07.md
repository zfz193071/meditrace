# MT-07 资料包、版本与草稿恢复

目标：一个包可以持续补资料，任何结果都能确定引用哪个版本。

先读：[领域实体、资料变更](../DOMAIN-AND-API.md)。范围：packets Module、列表／详情／revisions HTTP Interface。

## 实施范围

- 创建、列表、标题、当前状态、到期时间；创建要求 synthetic_data_ack，不把此勾选当成真实隐私保障。
- 上传候选文件与 committed revision 分开；保存集合时校验归属、ready 状态、合计限制和 expected_revision。
- replace/remove/add 产生新 Document 集合和 manifest hash，旧 revision 不修改。
- 服务端保存草稿、最近操作位置的非敏感元数据；前端登录／支付回跳只带 ID。
- 定义删除 tombstone Interface，实际物理清理交 MT-18；所有读取立即尊重 deleted_at/expires_at。

## 验收

- [ ] 两个同时保存 revision 的请求只有一个成功，另一个 409，客户端能取最新版本。
- [ ] 外包 document_id、未解析文件、重复文件成员／超限集合无法提交。
- [ ] 增补／替换不改变历史 manifest 或页内容，旧 run 的 stale 可确定计算。
- [ ] 登录过期重登、支付回跳和刷新后恢复最后保存草稿；无文本写入 URL／localStorage。
- [ ] 包列表按 owner 限定，稳定分页，10 包与存储配额并发正确。

验证：API 集成、版本竞争、历史不变性与安全恢复测试。
