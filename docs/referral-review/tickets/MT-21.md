# MT-21 退役旧产品入口与发布检查迁移

目标：上线新产品时不遗留可直接访问的旧诊断、聊天或链上通道。

先读：ARCHITECTURE 部署迁移。范围：`main.py`、旧路由／页面、旧 Issue 模板、部署与测试脚本、部署文档。

## 实施范围

- 枚举全部旧读／写／流式／诊断／报告／验证／链上入口，包括重复路由；统一 410，不仅隐藏导航。
- 旧 `/chat`、history、verify 页面转到带退役说明的新入口；新首页不保留诊断／合规承诺。
- 新应用启动不要求 Web3/IPFS 凭据，不初始化旧网络客户端；历史合约代码和旧数据库保留，不删除用户数据。
- 更新 `deploy-vercel.sh` 和回归测试为新 readiness，追加迁移 allowlist，防止执行旧破坏性 SQL。
- 定义安全回滚候选：先有关闭旧接口的兼容基线；禁止自动回滚到恢复旧公开资料读取的版本。
- 用新工单入口替换默认旧聊天优化 Issue 模板，保留历史内容可追踪。

## 验收

- [ ] 直接对所有旧入口发出各种已支持方法均不能读旧资料、调用模型或上链。
- [ ] 新配置不带钱包／Pinata／RPC 也可启动、构建、部署；旧数据原样保留。
- [ ] 发布 verify 全是 GET，无建包、AI、支付或链上副作用。
- [ ] 部署／迁移／安全回滚离线测试通过，回退失败不会谎报成功。
- [ ] 新旧文档的“现有／已退役／计划”状态准确，无失效的新导航。

验证：路由枚举回归、禁用客户端 spy、发布脚本 mock 测试，按项目规范记录相应 BUGFIX 文档。
