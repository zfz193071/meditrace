# MT-20 评估工具、冻结集和质量报告

目标：用可复现证据说明系统做对了什么、在哪些情况下失败。

先读：[完整评估规范与门槛](../QUALITY-AND-RELEASE.md)。范围：`evals/referral-review`、golden/replay、版本化报告和 `/evaluation` 展示数据。

## 实施范围

- 实现规则基线和当前提取+核对流程评估，分开发／冻结测试集，指标保留分母与失败样本。
- 输出事实准确性、引用存在／支持性、Finding precision/recall、负例误报、tokens／成本／耗时。
- 默认 Fake/replay，真实模式必须显式开关和 max-cost；复用费用控制，测试不得绕过全站预算。
- 真实评估保存去敏可回放输出、版本 manifest 和数据来源；记录 replay 与真实测量差别。
- 建立回归门槛，展示真实失败案例和不支持范围；不把小样本结果称作临床验证。

- 优先交付离线 runner、指标定义、报告结构及失败案例呈现，实施顺序排在 MT-16 后、MT-17 前；缺标注复核／预算时明确列缺项，不把生成的报告模板称为评估完成。
- 给求职材料提供证据索引：关键事实、引用支持性、漏报／误报、成本／延迟分别关联版本和报告；测试通过数量不当作模型准确率或业务提效指标。
- 报告收录至少两个可复现失败或限制案例，解释预期／实际、用户影响及处理方式；故障注入、确定性拒绝与真实模型错误分别标注，不编造实测失败。

## 验收

- [ ] 至少 30 个包、10/20 划分和 gold 复核齐全，冻结集达到 QUALITY 所有门槛。
- [ ] 受控真实模型评估已实际运行且预算获授权；Fake/replay 成绩不能替代此项。
- [ ] 缺引用／不支持引文、幻觉、漏报、误报可独立计分；失败不从统计中消失。
- [ ] 报告可在无模型 Key 环境从录制输出重算同样指标，标记为 replay。
- [ ] 模型／提示／清单／解析变化时能运行回归并明确是否需要新真实评估。

- [ ] 报告有可链接的失败／限制案例与版本，清楚区分真实模型、Fake、replay 及故障注入；没有数据的指标显示未测。

验证：指标手算小样例、runner 费用上限／异常中断测试、真实评估与结果复算。未获模型预算时标 BLOCKED 并继续可独立的离线工作。
