# MT-01 工程基线、契约与配置模式

目标：后续模块在同一可构建、可测试、默认不花费模型费用的工程基线上开发。

先读：[架构](../ARCHITECTURE.md)、[契约](../DOMAIN-AND-API.md)、根 AGENTS.md。涉及现有 `src/frontend/package.json`、后端 requirements、`vercel.json`、新 `referral_review/config.py` 和 contracts 目录。

## 实施范围

- 核实并锁定受维护且兼容 Vercel 的 Next.js／React／Python／依赖版本，清理重复依赖声明的维护歧义，保留可运行锁文件及升级记录。
- 建立新模块目录、错误 envelope、request_id、时间／ID 格式、Pydantic Schema 和 OpenAPI 导出、前端类型生成，不实现空壳全套业务。
- 配置分为 bundled demo、sandbox、受邀 real，生产禁用 Fake 身份／dev grant 后门；真实 AI 默认关、预算默认 0，缺关键配置 fail closed。
- 固定环境变量表：数据库、OAuth、会话加密、Blob、Stripe test、模型、价格、预算、邀请名单、运维凭据；区分 build-time 与 runtime，不提交凭据。
- 新路由集中 `/api/v1`，与现有 Vercel rewrite 相容；生成 `scripts/check-referral-contracts` 或等效命令。

## 验收

- [ ] 前端生产 build、后端 import／最小新路由通过，旧部署脚本回归不被无关更改破坏。
- [ ] 相同 Schema 产生确定的 TS／OpenAPI，手工改变生成文件可由 CI 检出。
- [ ] 缺密钥时启动可提供 demo 与 readiness，真实模型入口明确不可用；不存在静默真实→假成功降级。
- [ ] 生产构建中无法启用开发身份头或任意账号 grant；错误格式不含秘密。
- [ ] 版本、构建大小、运行时兼容和依赖审计结果写入证据。

验证：构建、配置矩阵单元测试、Schema golden 测试。所有调用使用本地 Fake，不启动或停止用户服务。公共工单关闭标准见 [总表](../README.md)。
