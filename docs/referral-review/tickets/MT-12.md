# MT-12 人工处理、审核版本与确认快照

目标：工作人员能对事项作出明确决定，且重新核对不会覆盖人工工作。

先读：[资料变更与审核](../DOMAIN-AND-API.md)。范围：reviews Module、resolutions、handoff draft、confirm、review-history。

## 实施范围

- open/resolved/dismissed/unresolved 状态与 reopen；所有处理 append-only，保留操作者、理由、版本和时间。
- 人工修正是覆盖层，标注 Reviewer supplied；原始 Fact 和 Evidence 不可修改。
- expected_review_version 乐观锁；run／revision 失效时拒绝当前审核写入。
- 确认生成不可变审核快照；未解决事项和身份警示不会因确认消失。
- 纯人工模式可编辑确认，但必须标明未经自动核对，不能复用伪造 run_id。

## 验收

- [ ] 尚有 open 事项不能确认；dismiss/defer 缺理由不通过；有 unresolved 可确认并保留明显状态。
- [ ] 两人／两个 tab 同时更新同 review_version，第二个 409，已保存内容不被覆盖。
- [ ] 用户修改无法改动 Fact 引文；新 run 不静默继承旧决定。
- [ ] 确认后再编辑产生新 review_version，已有快照 payload/hash 不变。
- [ ] 未解决身份问题进入快照顶部警示；人工新增无证据事实明确 provenance。

验证：状态转换、并发、跨版本和快照不变性测试，不调用模型。
