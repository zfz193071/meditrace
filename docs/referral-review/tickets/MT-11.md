# MT-11 核对执行、幂等与中断恢复

目标：在 Vercel 请求时限内完成一次有持久状态的核对，不因重试重复派发模型。

先读：[Run 状态机与路由](../DOMAIN-AND-API.md)、ARCHITECTURE 执行与恢复。

## 实施范围

- create pending、execute、GET、cancel-pending、reconcile；保存配置版本、输入哈希和 provenance。
- execute 先做归属／资料／状态检查，然后原子预留，再持久化派发标记并调用 extraction/checklist。
- 首次 execute 在请求内 await，重复执行按状态返回；不使用响应后后台任务、进程内队列或 GET 触发模型。
- 180 秒应用期限、120 秒模型期限、240 秒 lease、pending 到期；实例死亡后的未知费用和状态恢复。
- 结果固化与账本结算事务处理；源版本变化不丢旧结果，删除 tombstone 时丢弃内容并结算费用。

## 验收

- [ ] 相同 key 和 payload 复用批次，不同 payload 409；客户端连续点击只产生一次派发。
- [ ] 不同实例争抢同 run，仅一个进入调用；terminal 状态重复 execute 不请求模型。
- [ ] 分别在 reserve 前后、派发标记前后、响应收到后／事务提交前注入故障，状态和费用符合契约。
- [ ] 刷新／GET 不产生 AI 请求；网络失联后可查看 run，unknown 不自动重跑。
- [ ] 全部批次标明 fake/replay/real、模型／提示／清单／资料版本，失败不显示成功摘要。

验证：API 契约、Fake 调用计数、多实例竞争及故障注入；真实执行只通过用户明确触发。
