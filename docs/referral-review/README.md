## 求职导向的实施优先级（2026-10-22 调整）

完整讨论与岗位／签证边界见 [新西兰求职定位与执行计划](NEW-ZEALAND-JOB-SEARCH.md)。后续功能范围基本符合四项建议；本次调整实施顺序并补齐明确交付物，不改工单编号、前置依赖、当前状态或最终发布门槛。

| 顺序 | 实施工作 | 求职可检查的产物 |
| --- | --- | --- |
| 1 | MT-15 核心审核闭环 | 双侧证据、人工决定、版本变化、确认与导出 |
| 2 | MT-16 免登录示例 | 正常／缺附件／身份冲突三例，英文首页与实际代码入口 |
| 3 | MT-20 离线部分；满足标注及预算条件后做真实评估 | 可复现指标、失败案例、版本及测量边界 |
| 4 | MT-23 初稿阶段 | 60—90 秒英文演示初剪、英文 README、技术讲解和两类岗位简历要点 |
| 5 | MT-17 → MT-18 → MT-19 → MT-21，再完成 MT-22 | 测试支付、数据生命周期、运维、旧入口退役及完整集成验收 |
| 6 | MT-23 最终材料 → MT-24 | 对照实测修订成片及文案，完成部署和线上验收 |

前置 MT-02—14 的外部验收缺项在具备配置／操作者条件时穿插补齐，不延后隐藏。MT-20 没有预算时继续可独立的离线工作；有未满足依赖仍保持 TODO。MT-23 初稿可以提前编写，但只有 MT-16／20／22 完成并满足本票验收才能关闭。此安排是单代理工作顺序，不授权多代理或后台并行任务。

优先完成演示不等于新增提前发布路径：正式部署仍执行 MT-24 和 QUALITY 全部门槛；不删除支付／安全／真实评估要求，也不为求职临时添加 OCR、团队协作或 HealthLink 集成。

## 工单关闭规则

状态为 `TODO → IN_PROGRESS → DONE`；缺外部配置或人工验收时记 `BLOCKED` 并列出具体缺项，不用 Mock 成功替代外部集成验收。依赖未完成则保持 TODO。

每票必须写明：改动文件／提交、验收项逐项结果、命令及结果、失败路径证据、残余限制。若修复既有 bug，增加项目要求的 BUGFIX 文档。所有新增必需工作必须归入现有票或显式新增票并更新覆盖表；禁止把必要工作标为“后续优化”后关闭版本。

V1 完成是 24 票全部 DONE 且 QUALITY-AND-RELEASE 的发布门槛通过，不意味着已有真实医疗用户、临床验证或商业收入。
