# V1 产品需求

## 任务与定位

MediTrace — Referral Review Copilot。面向诊所转诊接收人员，核对一次门诊转诊资料包，交付可追溯、经人工确认的交接摘要。求职目标是展示 AI 应用和全栈工程能力；第一版是合成资料演示产品。

一位账号拥有自己的工作区，独立完成接收和核对。V1 不做机构、团队邀请、多人实时协作或患者账号。资料包只代表一次任务，不跨包合并患者身份。

## 范围与规格

| 编号 | 必须完成的行为 |
| --- | --- |
| R01 | 英文首页与无需登录的固定示例；显著区分预先生成结果、模拟运行和真实模型运行 |
| R02 | GitHub 登录；服务端身份与资料归属校验；登录／测试购买返回后恢复已保存的资料与操作位置 |
| R03 | 导入文字 PDF 或粘贴文字；文件级失败反馈、大小／页数限制、私有保存、不可变资料版本 |

| R05 | 每个采纳的提取事实有可验证的原文引用；冲突显示双方证据；缺失项展示要求和检查范围 |

## 首版接收清单

固定 `outpatient-referral-demo@1`，标题为 “Outpatient Referral — Demonstration Checklist”。它是演示工作清单，不引用医疗接收资格或临床诊疗阈值。检查项固定如下：

| Rule ID | 要求 | 资料存在／不确定时的处理 |
| --- | --- | --- |
| C01 | 患者姓名有记录 | 同时存在差异姓名时提示身份待核对，不合并别名 |
| C02 | 出生日期有记录 | 完整日期之间不一致时提示身份待核对；歧义日期保留原文 |
| C03 | 转诊方及联系信息有记录 | 只检查提供与否，不自动联系、不验证联系电话真实性 |
| C04 | 接收专科或接收方有记录 | 未提供则提示；不推荐应该转什么科 |
| C05 | 转诊原因有记录 | 保留原有表达，不推断诊断 |
| C06 | 当前用药状态有记录 | 区分列出药物、明确未用药、不清楚、未提供 |
| C07 | 过敏状态有记录 | 区分有过敏、明确无已知过敏、不清楚、未提供 |
| C08 | 明确声称已附上的报告可在资料包中找到 | 匹配不到则提示“未找到匹配附件，需人工核对”，不声称患者未做检查 |

不强制所有人提供某项医学检查。C06/C07 为 unknown 时有记录但仍产生“需澄清”；明确 none 为有记录。药物剂量可作为提取事实，但首版不判断剂量是否合理、也不推断某次变更是否合法。

## 输入限制（产品约束，不是平台最大值）

- 单包最多 5 份有效文件，每份 PDF 最大 2 MiB，单包累计 PDF 原始字节最多 10 MiB、总页数最多 25 页。
- 粘贴文本是一份 Document，上限 10,000 个 Unicode code point；单包解析后的合计文本上限 30,000 code point。
- 模型完整请求（含提示词、Schema、资料）上限 16,000 tokens，输出上限 6,000 tokens。不能安全估计输入 token 时使用已验证的保守字节上界并提前拒绝，不截断。
- 英文资料为支持及评估范围；姓名、单位和 Unicode 引用不能被破坏。多语言医学文本不作质量承诺。
- 不支持图片、扫描件、加密 PDF、需要密码的 PDF、损坏文件、附件套娃、压缩包和 URL 抓取。含无法提取文字的非空页时阻止自动核对该包，提示替换为文字版本；不能静默丢页。
- 每账号同时最多 10 个未删除资料包，存储上限 100 MiB；同时只允许 1 个模型任务，全站默认最多 2 个。默认全站 AI 预算为零，配置有效预算后才能启用真实请求。
- 全站原件存储预算默认 1 GiB，达到上限拒绝新上传但仍允许读取／删除；与账号存储配额同时事务预留，避免注册多个账号绕过总限制。
- 原件对象数同时受限：每账号最多 50 个、全站最多 5,120 个（MT-05 存储防滥用上限）；在途上传、历史版本原件和待清理对象均计数，确认物理清理后才释放。单包 5 份有效文件的限制另算，历史版本不占当前版本的有效文件名额，但占上述存储预算。

## 页面及主要流程

| 路径 | 页面职责 |
| --- | --- |
| `/` | 英文定位、固定示例入口、架构与评估入口，清晰说明合成资料与作品状态 |
| `/demo` | 无登录查看 3 个固定案例；内存内操作审核／导出／重置，不调用模型、不创建服务端患者资料 |
| `/workspace` | 登录后的资料包列表、新建、最近状态、保留期限及删除 |
| `/workspace/packets/{id}` | 导入区、资料清单、运行状态、事实／事项、证据面板、人工审核、确认与导出 |
| `/account` | 登录信息、测试会员到期时间／额度、测试购买、退出及删除账号 |
| `/evaluation` | 评估方法、版本、指标、样本与限制；不输出私人运行日志 |

工作区主流程：创建空包 → 上传／粘贴并解析 → 选择纳入版本的资料 → 保存新版本 → 主动核对 → 逐项处理 → 人工确认 → 导出。未登录者可使用固定示例；自定义导入先登录。未购买者可导入、手动记录、审核和导出，不可调用真实 AI。

桌面采用资料列表、事项列表、原文证据阅读区；选中一个冲突时同时显示两份来源的页内文字摘录。原始 PDF 的页预览作为辅助，引用位置以版本化提取文字为准，不承诺像素级 PDF 框选。

## 人工完成的含义

- 所有事项必须从 `open` 变为 `resolved`、`dismissed` 或 `unresolved`，才能确认审核；后两者必须填写理由。
- “完成审核”不等于“资料齐全”。若有未解决事项，交接摘要显示 “Reviewed — unresolved items remain”。
- 出生日期等身份差异未解决时允许导出，但必须在摘要顶部突出“Identity unresolved”；不能把多个身份自动合成同一患者。
- 用户添加的内容注明“Reviewer supplied”，关联修改历史；没有来源时不能伪造引文。
- 源资料修改后，旧快照仍可作为历史下载并带版本及“非当前版本”提示；当前版本必须重新核对或明确走纯人工流程。

## 运行与付费模式

1. **固定示例**：离线数据和预先生成结果，免费、无需登录，所有改动仅在页面内存中，刷新重置。
2. **会员沙箱**：GitHub 登录、Stripe 测试 Checkout，一次购买获得测试会员有效期 30 天／20 次模拟核对，不自动续费、不收真实费用。测试商品金额仅为沙箱配置，页面明确“Test payment — no real charge”。
3. **受邀真实核对**：后端 `REAL_AI_ENABLED`、服务端邀请名单、有效测试会员、用户额度、预算及价格配置均通过才调用 DeepSeek；仅用于经授权的合成资料验证。公共沙箱支付本身不会赋予真实模型权限。

这是对历史会员要求在求职作品中的具体落地，不是正式收费 SaaS。正式价格、真实支付账户及商业托管方案不属于 V1 上线范围；不能在 Hobby 部署中打开真实收款。现有平台明确 Hobby 用于个人非商业用途，参见 [官方说明](https://vercel.com/docs/plans/hobby)。

## 明确排除

诊断聊天、医学概率、治疗建议、自动临床分诊、自动拒收、保险预授权、医疗编码、RAG 医学知识库、网页搜索、OCR、院内系统／FHIR 集成、邮件／传真发送、多人协作、患者长期档案、小程序、钱包、区块链和 IPFS。交接摘要不强制一页；重要事实和未解决项可以跨页，不能静默裁剪。

## 求职叙事与应用验证

主张：“上传资料，核对缺失和差异，点击证据，人工完成交接。”展示复杂状态、来源验证、失败恢复、预算控制和评估结果，不把接入多个框架当成果。

商业价值是待验证假设：未来由接收人员比较人工与辅助核对的耗时、漏项和误报负担。用户访谈和付费试点不阻塞本版开发完成，但不得把尚未发生的效果或客户写进首页。
